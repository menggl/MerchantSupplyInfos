# 一、字典数据接口文档

- 基础地址：`http://8.141.125.139`
- 全部接口返回 `application/json`
- 数据均按 `sort` 字段升序排列；逻辑删除（`deleted=1`）的数据已被过滤

## 1. 获取完整字典层级（不推荐）
- 方法与地址：`GET /api/dict/all`
- 功能：返回品牌 → 系列 → 型号 → 配置的完整层级数据
- 说明：该接口的下级对象中父级 ID 字段可能为空（仅包含本级的 `*_id`、`*_name`、`sort` 以及下一级数组）
- curl 示例：
```bash
curl -X GET "http://8.141.125.139/api/dict/all" -H "Accept: application/json"
```
- 返回示例：
```json
[
  {
    "brand_id": 1,
    "brand_name": "Apple",
    "sort": 1,
    "seriesArr": [
      {
        "series_id": 10,
        "series_name": "iPhone",
        "sort": 1,
        "modelArr": [
          {
            "model_id": 100,
            "model_name": "iPhone 13",
            "sort": 1,
            "specArr": [
              { "spec_id": 1000, "spec_name": "128GB", "sort": 1 },
              { "spec_id": 1001, "spec_name": "256GB", "sort": 2 }
            ]
          }
        ]
      }
    ]
  }
]
```

## 2. 获取所有品牌

- 功能：返回全部品牌的基础信息
- 字段：`brand_id`、`brand_name`、`sort`
- curl 示例：
```bash
curl -X GET "http://saizanjibao.com/api/dict/brands" -H "Accept: application/json"
```
- 返回示例：
```json
[

]
```

## 3. 获取品牌详情（系列、型号、配置）
- 方法与地址：`GET /api/dict/brand-details/{brandId}`
- 功能：根据品牌 ID 获取该品牌下的所有系列、型号、配置信息。
- 路径参数：
  - `brandId`：品牌 ID（必填）
- 返回字段说明：
  - `brandId`：品牌 ID
  - `seriesArr`：系列列表
    - `id`：系列 ID
    - `series_name`：系列名称
    - `sort`：排序值
    - `modelArr`：型号列表（嵌套在系列下）
      - `id`：型号 ID
      - `model_name`：型号名称
      - `sort`：排序值
      - `specArr`：配置列表（嵌套在型号下）
        - `id`：配置 ID
        - `spec_name`：配置名称
        - `sort`：排序值
- 规则：
  - 仅返回 `deleted=0` 的有效数据
  - 各列表均按 `sort` 字段升序排列
  - 结构为 Brand -> Series -> Model -> Spec 的树形结构
- curl 示例：
```bash
curl -X GET "http://8.141.125.139/api/dict/brand-details/1" -H "Accept: application/json"
```
- 返回示例：
```json
{
  "brandId": 1,
  "seriesArr": [
    {
      "id": 10,
      "series_name": "iPhone",
      "sort": 1,
      "modelArr": [
        {
          "id": 100,
          "model_name": "iPhone 13",
          "sort": 1,
          "specArr": [
            { "id": 1000, "spec_name": "128GB", "sort": 1 },
            { "id": 1001, "spec_name": "256GB", "sort": 2 }
          ]
        }
      ]
    },
    {
      "id": 11,
      "series_name": "iPad",
      "sort": 2,
      "modelArr": []
    }
  ]
}
```

## 3. 发送短信验证码
- 方法与地址：`POST /api/sms/send-code`
- 功能：给指定手机号发送短信验证码，随机生成6位数验证码，有效期5分钟。需提供图形验证码校验。
- 请求头：
  - `Authorization: Bearer <token>`
- 请求体：
```json
{
  "phone": "13800000001",
  "captchaCode": "1234"
}
```
- 说明：
  - 图形验证码与 `wechatId+phone` 绑定，发送短信时只需提供 `captchaCode`。
  - 一个微信号一天最多发送5次。
- curl 示例：
```bash
curl -X POST "http://8.141.125.139/api/sms/send-code" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer token_0001" \
  -d '{ "phone": "13800000001", "captchaCode": "1234" }'
```
- 返回示例（成功）：
```json
{ "status": "success" }
```
- 返回示例（失败）：
```json
{
  "errorCode": "V0001",
  "message": "图形验证码错误"
}
```
- 错误码说明：
  - `V0001`: 图形验证码错误（无效或过期）
  - `SMS_FAILED`: 短信发送失败（包含具体错误信息）

## 2. 删除商户已上架的商品
- 方法与地址：`DELETE /api/merchants/products/{productId}`
- 功能：删除当前登录商户已上架的某个商品，实际上为逻辑删除（将 `isValid` 置为 `0`），后续查询接口将不再返回此商品。
- 请求头：
  - `Authorization: Bearer <token>`
- 路径参数：
  - `productId`：商品 ID（必填）
- 行为说明：
  - 仅允许删除当前登录商户自己的商品，删除其他商户商品会返回 400 错误（“无权操作该商品”）。
  - 已删除（`isValid=0`）的商品再次删除不会报错，但不会产生任何效果。
  - 删除后，该商品不会出现在分页查询和按机型查询接口中。
- curl 示例：
```bash
curl -X DELETE "http://8.141.125.139/api/merchants/products/1" \
  -H "Authorization: Bearer token_0001"
```

## 3. 修改商品上架状态（上架 / 下架）
- 方法与地址：`PUT /api/merchants/products/{productId}/state`
- 功能：修改当前登录商户某个商品的上架状态，仅修改 `state` 字段，不影响 `isValid`（是否删除）。
- 请求头：
  - `Authorization: Bearer <token>`
- 路径参数：
  - `productId`：商品 ID（必填）
- 查询参数：
  - `state`：商品状态（必填）
    - `1`：上架
    - `0`：下架
- 行为说明：
  - 仅允许操作当前登录商户自己的商品，否则返回 400 错误（“无权操作该商品”）。
  - 只能操作 `isValid=1` 的有效商品；已删除的商品会返回 400 错误（“商品不存在”）。
  - 新建商品或修改商品信息后，默认 `state=0`，需要调用本接口将其上架。
- curl 示例（下架商品）：
```bash
curl -X PUT "http://8.141.125.139/api/merchants/products/1/state?state=0" \
  -H "Authorization: Bearer token_0001"
```

  - `buyCount`：求购数量（必填，>0 的整数）
  - `minPrice`：期望收货最低单价（必填，>0 的整数，单位：元）
  - `maxPrice`：期望收货最高单价（必填，>0 的整数，且 `maxPrice >= minPrice`）
  - `deadline`：求购截止时间（必填，ISO8601 格式，如 `"2026-01-31T23:59:59"`）
  - `costIntegral`：本次求购需要消耗的积分（必填，>=0 的整数）
- 特别说明：
  - `cityCode` 不需要前端传入，后端会自动使用商户当前城市编码。
  - 同一商户、同一机型（品牌+系列+型号+配置）在同一产品类型（`productType`：新机或二手机）下，最多只能存在一条 `isValid=1` 的有效求购信息；若在相同 `productType` 下重复发布相同机型的求购信息，会返回 400 错误，错误信息为“该型号求购信息已存在”。
  - 不同 `productType`（例如同一机型的新机求购和二手机求购）可以各自存在一条有效记录，互不冲突。
  - 若商户未登录，返回 401。
  - 若商户会员已过期，返回 400，错误信息为“商户会员已过期”。
  - 若积分不足，返回 400，响应体包含错误码 `R0003`。
- 请求体示例：

# 七、积分充值、会员充值接口

## 1. 创建微信充值订单

- **接口描述**：创建一笔积分或会员充值订单，返回订单号和金额，供前端调起微信支付。
- **请求方式**：POST
- **接口地址**：`/api/pay/wechat/recharge`
- **请求头**：
-  - `Authorization: Bearer <token>`
- **请求体参数**（JSON）：

| 参数名          | 类型    | 必填 | 描述                               |
| :------------- | :------ | :--- | :--------------------------------- |
| rechargeType   | Integer | 是   | 充值类型：1=积分充值，2=会员充值   |
| integralAmount | Integer | 否   | 充值积分数量，rechargeType=1 时必填 |
| memberMonths   | Integer | 否   | 充值会员月数，rechargeType=2 时必填 |
| totalAmount    | Integer | 是   | 支付金额（单位：分）               |

- **请求示例**：

```bash
curl -X POST 'http://localhost:8080/api/pay/wechat/recharge' \
  -H 'Authorization: Bearer your_token_here' \
  -H 'Content-Type: application/json' \
  -d '{
    "rechargeType": 1,
    "integralAmount": 100,
    "memberMonths": null,
    "totalAmount": 1000
  }'
```

- **响应结果示例**：

```json
{
  "payment": {
    "appId": "wx8888888888888888",
    "timeStamp": "1739245345",
    "nonceStr": "5K8264ILTKCH16CQ2502SI8ZNMTM67VS",
    "package": "prepay_id=wx201410272009395522657a690389285100",
    "signType": "RSA",
    "paySign": "MOCK_SIGNATURE_FOR_TESTING..."
  },
  "order": {
    "out_trade_no": "202501151234567890abcdef",
    "amount": 1000,
    "rechargeId": 12345
  }
}
```

- **响应说明**：
  - `payment` 对象：包含微信小程序发起支付所需的全部参数 (`wx.requestPayment`)。
    - `appId`：小程序ID。
    - `timeStamp`：时间戳。
    - `nonceStr`：随机字符串。
    - `package`：统一下单接口返回的 prepay_id 参数值，提交格式如：prepay_id=***。
    - `signType`：签名算法，固定为 RSA。
    - `paySign`：签名。
  - `order` 对象：包含业务订单的基本信息。
    - `out_trade_no`：本系统生成的充值订单号，用于后续微信支付以及支付回调识别订单。
    - `amount`：本次充值的支付金额（单位：分）。
    - `rechargeId`：订单记录的主键ID。
  - 若参数不合法，会返回 HTTP 400。
  - 若 `Authorization` 失效或缺失，会返回 HTTP 401。

## 2. 微信支付回调（服务端调用）

- **接口描述**：微信支付平台支付成功后回调该接口，系统根据订单号完成积分或会员充值。此接口由微信服务器调用，小程序前端无需调用。
- **请求方式**：POST
- **接口地址**：`/api/pay/wechat/notify`
- **请求体参数**（JSON，示例字段）：

| 参数名         | 类型    | 必填 | 描述                          |
| :------------ | :------ | :--- | :---------------------------- |
| outTradeNo    | String  | 是   | 商户订单号（系统订单号）      |
| transactionId | String  | 否   | 微信支付订单号                |
| totalAmount   | Integer | 是   | 实际支付金额（单位：分）      |
| tradeState    | String  | 是   | 支付状态，SUCCESS 表示支付成功 |

- **回调处理规则（简要说明）**：
  - 若 `tradeState` 不为 `SUCCESS`，接口直接返回 `"success"`，不做任何数据更新。
  - 若为 `SUCCESS`：
    - 根据 `outTradeNo` 查询充值订单。
    - 校验订单是否存在、是否未完成。
    - 校验回调金额 `totalAmount` 是否等于订单金额。
    - 根据订单类型完成相应充值：
      - 积分充值：增加会员积分，写入积分变动明细。
      - 会员充值：更新会员有效期与状态，刷新登录缓存。
    - 更新订单状态为已完成并保存微信订单号。

- **响应结果**：
  - 成功处理（包含非 SUCCESS 状态但格式正确）：HTTP 200，响应体 `"success"`。
  - 参数错误或订单校验失败：HTTP 400，响应体 `"invalid request"` 或 `"fail"`。

- **请求体参数**（JSON）：

# 附录：错误码说明

所有接口在返回 HTTP 400/401 状态码时，响应体中可能包含 `errorCode` 字段，用于前端进行特定业务逻辑处理。

| 错误码 | 含义 | HTTP状态码 | 建议前端处理方式 |
| :--- | :--- | :--- | :--- |
| `A0001` | Token缺失或无效 | 401 | 跳转至登录页，引导用户重新登录 |
| `A0002` | Token校验失败（格式错误/过期） | 401 | 跳转至登录页，引导用户重新登录 |
| `R0001` | 商户信息未完善（未绑定手机号） | 401 | 引导用户进入完善信息页面绑定手机号 |
| `R0002` | 商户会员已过期 | 401 | 弹窗提示会员过期，引导用户进入充值页面 |
| `R0003` | 积分不足 | 400 | 弹窗提示积分不足，引导用户进行充值 |

**响应体示例**：

```json
{
  "errorCode": "R0002",
  "error": "商户会员已过期"
}
```
